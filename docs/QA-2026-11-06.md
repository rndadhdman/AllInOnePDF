# QA pass, 6 November 2026

Build: `1.0.0+ef629e7` (main, clean tree), web host (`web-qa` launch profile, Blazor Server, Development) on an empty
data folder (`scratchpad\qa-data`, cleared of two leftover `.aiopub` files from an earlier run before starting).
Browser: the Claude desktop browser pane, 1024×768 CSS px natively; narrow checks at 1000×700 and 600×800.

## Summary

Convert, Reader, Themes and the Creator basically work: every Markdown → target conversion succeeded and was fast,
round trips through Word and HTML come back almost byte-identical, the theme builder's undo/redo, validation,
recovery bar and exact preview behave, and the Creator's insert/duplicate/delete/move keys, autosave, recovery and
"Continue where you left off" all work.

The serious problems are:

* the Creator's page model (Design sheets, "Page n of m", tree markers, Preview) counts the placeholder of an
  **empty image module** but Export PDF does not, so the advertised "sheets agree with the PDF" breaks on the stock
  Flyer template after one edit (Design 2 pages, PDF 1);
* **Theme…** in the Creator throws away the publication's own page orientation while the inspector still shows it;
* dropping several large files on the **empty** Convert page silently loses some of them (JS exception);
* after a second upload, an invisible-but-clickable **"Completed" progress overlay** sits over the Convert toolbar
  and eats clicks on "Set target for all" and "Clear completed";
* the Reader's **Convert this** button only navigates to Convert; it never adds the document.

### Findings

**C1. Broken — dropping several large files on the empty Convert page loses files silently.**
Steps: empty Convert page → drop five 2.5 MB `.md` files at once. Expected: five rows. Actual: three rows, no
message; console shows `JSException: Cannot read properties of null (reading '_blazorFilesById')` from
`FileDropZone.OnFileUploadedAsync` (`Components/Converting/FileDropZone.razor:215`). Dropping five more onto the
non-empty list adds all five. Cause: `Pages/Home.razor:32-47` renders two different `FileDropZone` instances for
the empty and the non-empty state, so the first added file re-renders the page and disposes the input that is still
streaming the rest; the `catch` at `FileDropZone.razor:221` does not include `JSException`, so the user gets no
toast. (Small files usually finish before the swap, which is why the 17-file drop worked.)

**C2. Broken — "Completed" progress overlay covers the toolbar after a second upload.**

normal. Actual: FluentInputFile's `.inputfile-progress` block ("Completed" under a progress bar) stays
`visibility: visible` at x 350–883, y 250–300 (1024 px window), drawn over "N files · size", "Set target for all"
and "Clear completed". `elementFromPoint` at the centre of "Clear completed" returns the overlay: two real clicks on
Clear completed did nothing. `Components/Converting/FileDropZone.razor:10` (the compact layout needs to hide or
place the input-file progress template).

**C3. Noticed — options drawer tabs run together.** The two tabs read "PDF outputReading Markdown" with no gap and

### Findings

**K1. Broken — Design/Preview page count disagrees with the exported PDF when an image module has no image.**
Steps A: Blank → insert all twelve modules → put 18 long paragraphs in the Text module → Design says "Page n of 7",
the tree shows "Contents p. 6–7", Preview says "Page 1 of 7" → Export PDF → the PDF has **6** pages. Delete the empty
Image module → Design/Preview 6, PDF 6. Steps B (stock template): Flyer → select the headline → Ctrl+D → Design
"Page 1 of 2 / Page 2 of 2" → Export PDF → **1** page. After choosing an image for the hero module the counts agree
(3/3). Cause: the page map and Preview render with `ShowPlaceholders = true`
(`Services/CreatorState.cs:221`, `Components/Creator/CreatorPreview.razor:202`), so an empty image module reserves
its placeholder box, while Export PDF renders without placeholders (`Pages/CreatorBuilder.razor.cs:435`). Every
template with an empty image (Flyer, Newsletter, Report…) is affected out of the box.

**K2. Broken — Theme… discards the publication's page settings and the inspector does not notice.**
Steps: Flyer → Inspector (nothing selected) → Page → Landscape → Export PDF (MediaBox 842×595, landscape) →
More → Theme… → Night → Use theme. Expected (Help/README: page, header and footer are per publication): stays
landscape. Actual: the canvas goes back to portrait and the exported PDF is 595×842, while the Orientation control
still shows **Landscape** selected.

**K3. Missing — Creator export formats.** README: "export to PDF or any other format". More offers only Word, HTML,
EPUB, Markdown and plain text; Excel, PowerPoint and PNG/JPEG/WebP (which Convert supports) are absent.

**K4. Missing — Help does not describe the new page features.** CHANGELOG [Unreleased] adds page sheets, "Add
page", "Continues on page n" marks, the tree's "Page n" markers and the Preview keys; `Pages/Help.razor` mentions
none of them, and its Creator keyboard table has no Preview keys (PageUp/PageDown, arrows, Home/End, wheel).

**K5. Noticed — the unsaved-changes dialog claims a draft that is not written.** Steps: open the Report template,
change nothing, press Back. The dialog says the changes "are kept only as a recovery draft that is offered back the
next time you open it", but no draft is written and nothing appears under "Continue where you left off".
Status: fixed (leaving a new template or theme that was not changed no longer asks at all; with changes the autosaved draft does exist, so the wording now says "if you leave without saving" next to the new "Save and leave").

**K6. Noticed — Design canvas footer shows "1 / n".** The Blank template's footer token `{pages}` renders as "n" on
the canvas although the sheets know the real count.
Status: fixed (the canvas header and footer get the sheet count, which follows `CreatorState.PageMap` once the first render lands).

**K7. Noticed — "Add row" pill overlaps content.** On the Report title page it sits on top of "5 November 2026";
on the Blank page it overlaps the bottom of the "Add module" box.
Status: fixed (the pill appears only while the pointer is on a 24 px band over the row boundary, or when it has keyboard focus; it no longer shows over a hovered or selected section).

**K8. Noticed — Report template prints a page number "1" on its title page.**
Status: fixed (the Report template sets Header/Footer "Show on the first page" off; the canvas follows that setting too, so page 1 shows no strip).

**K9. Noticed — layout overflow.** At 1000×700 the builder's content area is wider than the window (scrollWidth
1150 vs 770 px), giving a horizontal scrollbar; pressing End in Preview also scrolled the whole builder up by
about 8 px so the top bar was cut. At 600×800 the toolbar wraps and the Save button is clipped at the right edge.
Status: fixed (the closed drawers were widening the builder: `.cr-main` now clips them; the Preview strip scrolls itself instead of `scrollIntoView`, so End no longer scrolls the builder; at 600 px Save and Export PDF sit on the wrapped second row, nothing clipped).

**K10. Noticed — zoom is not available below 1100 px** (`Pages/CreatorBuilder.razor:58` hides it with `_narrow`),
although Help says the zoom list sits next to Design and Preview.
Status: fixed (below 1100 px the More menu starts with the zoom levels as radio items, then Theme…).

**K11. Noticed — Esc on a narrow window with no panel open does nothing.** Help: "Esc: close the side panels on a

Status: fixed (could not reproduce with focus on the canvas; Esc was ignored when focus stayed on a field inside a just-closed, now hidden drawer, so Esc from a hidden panel now clears the selection).

**K12. Noticed — imported packages are indistinguishable.** Importing `Shared copy.aiopub` adds a second "QA Pub"

**K13. Noticed — module Design tab background reads "None" next to a filled `#FFFFFF` value.**

**K14. Noticed — "Reset to saved" has no confirmation** (it discarded a deletion immediately); Save as… says "The
